## 1. الملخص التنفيذي

Storify هو نظام SaaS متكامل لإدارة المخازن والمحال التجارية، مصمم خصيصاً للسوق العربي. يوفر النظام حلاً شاملاً يغطي دورة حياة البيع الكاملة: من إدارة المنتجات والمخزون، مروراً بنقطة البيع والتقسيط، وصولاً إلى التقارير والتحليلات المتقدمة.

يعتمد النظام على معمارية Multi-tenant المعزولة، مما يتيح لكل عميل بيئة عمل مستقلة وآمنة تماماً، مع إدارة مركزية واحدة للمنصة.

> **الهدف الرئيسي:** توفير نظام إدارة احترافي ومتكامل بسعر اشتراك شهري معقول، يمكّن أصحاب المحلات من التحكم الكامل في أعمالهم من أي مكان.

## 2. المشكلة والحل

### 2.1 المشكلة الحالية
- أصحاب المحلات يعتمدون على Excel أو دفاتر يدوية
- لا يوجد تتبع حقيقي للمبيعات والأرباح في الوقت الفعلي
- إدارة التقسيط الداخلي تتم يدوياً وغير منظمة
- صعوبة متابعة عدة فروع من مكان واحد
- الأنظمة المتاحة إما مكلفة جداً أو غير مناسبة للسوق العربي

### 2.2 الحل — Storify
- نظام سحابي متكامل يعمل من أي متصفح بدون تثبيت
- واجهة عربية بالكامل سهلة الاستخدام
- إدارة مخزون ذكية مع تنبيهات نفاد المخزون
- نقطة بيع سريعة تدعم الكاش والكارت والتقسيط
- عقود تقسيط رسمية بتوقيع رقمي وصور مستندات
- تقارير لحظية ولوحة تحكم شاملة لكل الفروع

## 6. نظام التقسيط

### 6.1 التقسيط الداخلي
- الكاشير يبدأ العقد من شاشة البيع
- إدخال: المقدم، عدد الأقساط، تاريخ أول قسط، الضامن، الفائدة
- رفع: صور بطاقة الهوية + التوقيع الرقمي
- العقد يذهب للمدير للموافقة → طباعة PDF → تسجيل الدفعات

### 6.2 التقسيط الخارجي
- البيع يُسجَّل كـ cash (المحل يأخذ أمواله فوراً)
- تسجيل: شركة التمويل + رقم مرجعي + عمولة %

### 6.3 العملات المتعددة
> لو العقد بالدولار، يتم تثبيت سعر الصرف وقت التوقيع. الأقساط تُحسب بنفس السعر الأصلي.

## 11. الأمان

- JWT Access Token (15 دقيقة) + Refresh Token (7 أيام) في HttpOnly Cookie
- كل tenant معزول في schema منفصل — استحالة الوصول لبيانات tenant آخر
- Zod validation على كل request
- Rate limiting لمنع Brute Force
- NUMERIC(15,4) لجميع الأرقام المالية — بدون floating point errors
- تشفير كلمات المرور: SHA-256 + salt عشوائي

## 14. طرق الدفع والرسوم — Payment Methods & Fees
> **تحديث v1.1** — أضيف أبريل 2026

### 14.1 المشكلة قبل التحديث
كل طريقة دفع ليها رسوم (fees) — إهمالها يعني تقارير مالية غير دقيقة وخسائر صامتة غير مرصودة.

| طريقة الدفع | الـ Fee النموذجية | من يتحملها؟ | كيف تُحسب؟ |
|---|---|---|---|
| فيزا / ماستركارد | 1.5% — 2.5% | المحل عادةً أو بالاتفاق | % من قيمة الفاتورة |
| فلوسة | 1.75% أو مبلغ ثابت | المحل | % أو ثابت حسب العقد مع البنك |
| إنستاباي | 0% — 0.5% | المحل | % صغيرة أو مجانية |
| Valu / Sympl | 2% — 5% | المحل دائماً | % من قيمة التمويل |
| تحويل بنكي | مبلغ ثابت | يتفاوت | ثابت لكل عملية |
| كاش | 0% | لا يوجد | — |

### 14.2 نموذج الـ Fees في النظام
كل tenant يُعرّف طرق الدفع الخاصة به وإعدادات الـ fees من إعدادات النظام.

**أنواع الـ fee:**
- `none` — لا توجد رسوم (كاش، إنستاباي)
- `percentage` — نسبة % من قيمة الفاتورة
- `fixed` — مبلغ ثابت لكل عملية
- `both` — نسبة + مبلغ ثابت معاً

**من يتحمل الـ fee:**
- `customer` — تُضاف للإجمالي والعميل يدفعها
- `merchant` — المحل يتحملها وتُسجَّل تلقائياً كمصروف
- `negotiable` — الكاشير يحدد وقت البيع

### 14.3 قواعد الحساب
| الحالة | الصيغة | مثال |
|---|---|---|
| percentage | fee = total × (pct ÷ 100) | 420 × 1.75% = 7.35 ج |
| fixed | fee = fee_fixed | 2.00 ج ثابتة |
| both | fee = (total × pct/100) + fixed | 420×1%+2 = 6.20 ج |
| none | fee = 0 | — |

### 14.4 صلاحيات الـ Fees حسب الدور

| Branch Manager | ✅ | ✅ (negotiable فقط) | ❌ |
| Cashier | ✅ عرض فقط | ✅ (negotiable فقط) | ❌ |

### 14.5 تأثير على تقرير الأرباح والخسائر
```
قبل التحديث:  صافي الربح = 46,950 ج  ← مبالغ فيه (fees غير مرصودة)
بعد التحديث: صافي الربح = 45,321 ج  ← دقيق
الفرق:        −1,629 ج/شهر خسائر كانت صامتة
```
