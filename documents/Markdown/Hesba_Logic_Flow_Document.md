## 1. تدفق تسجيل العميل الجديد

```
[START] العميل يفتح صفحة التسجيل
   ↓
[1] إدخال: اسم المتجر، subdomain، اسم المالك، البريد، كلمة المرور
   ↓
[?] هل الـ subdomain متاح؟
   ├── ❌ لا → خطأ: "الاسم محجوز، جرّب اسماً آخر"
   └── ✅ نعم ↓
[2] اختيار الباقة: Starter / Professional / Enterprise
   ↓
[3] بدء فترة تجريبية مجانية 14 يوم (بدون بطاقة ائتمان)
   ↓
[4] إنشاء الـ Tenant في Master DB
   ↓
[5] CREATE SCHEMA tenant_{subdomain} في PostgreSQL
   ↓
[6] تشغيل Migrations → إنشاء 25+ جدول تلقائياً
   ↓
[7] Seed البيانات الافتراضية
    - 5 أدوار افتراضية
    - فرع رئيسي
    - إعدادات افتراضية
    - عملة EGP
    - تصنيفات مصروفات
   ↓
[8] إنشاء Super Admin user
   ↓
[9] إرسال بريد ترحيبي + رابط الدخول
   ↓
[END ✅] العميل جاهز — {subdomain}.hesbaapp.com
```

## 2. تدفق تسجيل الدخول

```
[START] المستخدم يفتح {subdomain}.hesbaapp.com
   ↓
[Tenant Middleware] استخراج الـ subdomain من الـ hostname
   ↓
[?] هل الـ tenant موجود وفعّال؟
   ├── ❌ لا → 404 — المتجر غير موجود
   └── ✅ نعم ↓
[?] هل الاشتراك ساري؟
   ├── ❌ لا → 402 — subscription_required
   └── ✅ نعم → فتح connection لـ schema الـ tenant
   ↓
[1] المستخدم يدخل البريد وكلمة المرور
   ↓
[?] هل البيانات صحيحة؟
   ├── ❌ لا → 401 — بيانات خاطئة
   └── ✅ نعم ↓
[2] إنشاء Access Token (15 دقيقة) + Refresh Token (7 أيام)
    Refresh Token → HttpOnly Cookie فقط
   ↓
[3] تسجيل last_login
   ↓
[END ✅] توجيه للـ Dashboard حسب الدور
```

> **Refresh Token Flow:** لما الـ Access Token ينتهي، النظام يجدده تلقائياً بالـ Refresh Token بدون أي انقطاع.

## 3. تدفق البيع — كاش وكارت

```
[START] الكاشير يفتح شاشة البيع (POS)
   ↓
[1] إضافة المنتجات: بالباركود (Scanner/كاميرا) أو البحث
   ↓
[?] هل الكمية متوفرة؟
   ├── ❌ لا → تنبيه: "الكمية غير متوفرة — متاح: X"
   └── ✅ نعم → إضافة للفاتورة
   ↓
[2] تطبيق الخصومات (اختياري)
    - خصم % على الفاتورة
    - خصم على منتج معين
    - كوبون/كود خصم
   ↓
[?] هل يوجد كوبون؟
   ├── ✅ نعم → التحقق من الصلاحية (تاريخ + عدد استخدامات)
   └── ❌ لا → المتابعة
   ↓
[3] حساب الإجمالي: المجموع + VAT - الخصومات
   ↓
[4] اختيار طريقة الدفع: كاش / كارت / عملة أجنبية
   ↓
[?] دفع بعملة أجنبية؟
   ├── ✅ نعم → تحديد العملة — حساب بسعر الصرف الحالي
   └── ❌ لا → الدفع بالجنيه
   ↓
[5] تأكيد الدفع → تسجيل في invoices + invoice_items
   ↓
[6] تحديث المخزون تلقائياً → stock_movement (out)
   ↓
[7] زيادة used_count للكوبون (إن وُجد)
   ↓
[END ✅] طباعة الفاتورة A4/A5 أو إرسال PDF
```

## 4. تدفق البيع — التقسيط الداخلي

```
[START] الكاشير يختار "بيع بالتقسيط الداخلي"
   ↓
[1] البحث عن العميل أو إنشاء جديد
   ↓
[?] عميل جديد؟
   ├── ✅ نعم → رفع صور بطاقة الهوية (أمام + خلف) → R2
   └── ❌ لا → استخدام البيانات الموجودة
   ↓
[2] إضافة المنتجات للفاتورة
   ↓
[3] إدخال بيانات العقد:
    - المقدم (مبلغ أو %)
    - عدد الأقساط
    - تاريخ أول قسط
    - فائدة (اختياري)
    - ضامن (اختياري)
   ↓
[4] النظام يحسب: (الإجمالي - المقدم + الفائدة) ÷ عدد الأقساط
   ↓
[?] عقد بعملة أجنبية؟
   ├── ✅ نعم → تثبيت سعر الصرف الحالي في العقد
   └── ❌ لا → بالجنيه
   ↓
[5] التوقيع الرقمي → PNG → R2
   ↓
[6] حفظ العقد بحالة: pending_approval
    ⚠️ البيع غير مكتمل — المخزون لم يتغير
   ↓
[7] إشعار للمدير (Branch Manager / Super Admin)
   ↓
[?] هل وافق المدير؟
   ├── ❌ لا → رفض العقد — إشعار للكاشير
   └── ✅ نعم → approved_by = manager_id
   ↓
[8] إتمام البيع: فاتورة + تحديث مخزون + استلام المقدم
   ↓
[9] إنشاء جدول الأقساط تلقائياً
    installment_payments: قسط لكل شهر بتاريخ الاستحقاق
   ↓
[END ✅] طباعة عقد التقسيط PDF (A4)
```

## 5. تدفق البيع — التقسيط الخارجي

```
[START] الكاشير يختار "تقسيط خارجي"
   ↓
[1] إضافة المنتجات للفاتورة
   ↓
[2] اختيار شركة التمويل: Valu / Sympl / بنك / غيره
   ↓
[3] إدخال رقم الطلب المرجعي من شركة التمويل
   ↓
[4] إدخال عمولة الشركة % (اختياري)
   ↓
[5] تسجيل الفاتورة كـ cash (payment_type = installment_external)
   ↓
[6] حفظ في external_financing: company_name, reference_no, commission_pct
   ↓
[7] تحديث المخزون
   ↓
[END ✅] طباعة الفاتورة — يظهر "تمويل خارجي: Valu"
```

> ⚠️ التكامل مع APIs شركات التمويل مخطط للمرحلة الثانية.

## 6. تدفق إدارة المخزون

### 6.1 إضافة منتج جديد
```
[1] إدخال: الاسم، الباركود، التصنيف، سعر التكلفة، سعر البيع، الوحدة
[2] اختيار نسبة VAT: 0% / 14% / مخصص
[3] رفع صورة المنتج (اختياري) → R2
[4] تحديد الحد الأدنى للمخزون (min_quantity)
[5] إدخال الكمية لكل فرع
[6] إنشاء stock record لكل فرع
[END ✅] المنتج متاح للبيع في POS
```

### 6.2 تنبيه نفاد المخزون
```
بعد كل عملية بيع:
[?] الكمية ≤ min_quantity؟
   ├── ❌ لا → لا يوجد تنبيه
   └── ✅ نعم → تنبيه في Dashboard للمدير وأمين المخزن
[END ✅] المدير ينشئ أمر شراء
```

## 7. تدفق تحويل المخزون بين الفروع

```
[1] تحديد: الفرع المُرسِل، الفرع المستقبِل، المنتجات والكميات
[?] الكمية متوفرة؟
   ├── ❌ لا → خطأ
   └── ✅ نعم → إنشاء طلب تحويل بحالة pending
[?] يحتاج موافقة مدير؟
   ├── ✅ نعم → إشعار للمدير
   └── ❌ لا → موافقة تلقائية
[بعد الموافقة]
   - stock_movement (out) من الفرع المُرسِل
   - stock_movement (in) للفرع المستقبِل
   - status = completed
[END ✅]
```

## 8. تدفق المرتجعات

```
[1] البحث عن الفاتورة الأصلية
[2] تحديد المنتجات المُرجَعة والكميات
[3] تحديد سبب المرتجع
[?] البضاعة تُعاد للمخزون؟
   ├── ✅ نعم → restock = true
   └── ❌ لا → restock = false (بضاعة تالفة)
[?] استرداد نقدي أم رصيد؟
   ├── refund → إرجاع نقدي/كارت
   └── credit → إضافة لـ customer.credit_balance
[تسجيل] returns + return_items
[تحديث] stock_movement (in) إن restock = true
[END ✅] طباعة إيصال المرتجع
```

```
[1] اختيار المورد أو إضافة جديد

[3] تحديد تاريخ التسليم
[?] يحتاج موافقة؟
   ├── ✅ نعم → إرسال للمدير

[5] تحديث المخزون تلقائياً → stock_movement (in)
[6] تحديث رصيد المورد (suppliers.balance)
[?] دفع فوري؟
   ├── ✅ نعم → تسجيل دفعة
```

## القواعد العامة للـ Flows

| القاعدة | التطبيق |
|---|---|
| كل request يمر بـ Tenant Middleware | subdomain → schema → حالة الاشتراك |
| كل action مالي يُسجَّل | audit trail كامل لكل عملية |
| المخزون يتحدث تلقائياً | بيع→خصم، استلام→إضافة، مرتجع→إضافة أو خصم |
| الموافقات تحمي العمليات الحساسة | تقسيط، مشتريات، مصروفات كبيرة |
| الملفات على Cloudflare R2 | صور، عقود PDF، بطاقات، توقيعات |
| BullMQ للعمليات الثقيلة | PDF، SMS، Excel — بدون تبطئة الـ server |

## 13. تدفق البيع المحدّث — مع الـ Payment Fees
> **تحديث v1.1** — يستبدل تدفق البيع القديم في القسمين 3 و 4

### 13.1 تدفق البيع العام (كاش / كارت / محافظ) — مع الـ Fees

```
[START] الكاشير يضيف المنتجات ويجهّز الفاتورة
   ↓
[1] حساب الإجمالي: المجموع + VAT - الخصومات
   ↓
[2] اختيار طريقة الدفع — النظام يعرض الـ fee مع كل طريقة
    مثال: [💵 كاش — 0%] [فيزا — 1.75%] [فلوسة — 2ج] [إنستاباي — 0%] [Valu]
   ↓
[?] هل طريقة الدفع عليها fees؟
   ├── ❌ لا (كاش / إنستاباي 0%) → إتمام البيع مباشرة
   └── ✅ نعم → حساب fee تلقائياً
   ↓
[3] حساب الـ fee:
    percentage → fee = total × (fee_pct / 100)
    fixed      → fee = fee_fixed
    both       → fee = (total × fee_pct/100) + fee_fixed
   ↓
[?] fee_bearer = negotiable؟
   ├── ✅ نعم → الكاشير يختار: العميل أم المحل
   └── ❌ لا  → محدد مسبقاً من الإعدادات
   ↓
[?] مين يتحمل الـ fee؟
   ├── customer → fee_added_to_total = true
   │              total_amount += fee_amount
   │              العميل يدفع: 420 + 7.35 = 427.35 ج
   └── merchant → total_amount لا يتغير
                  fee تُسجَّل كمصروف تلقائي بعد البيع
   ↓
[4] تأكيد الدفع — حفظ الفاتورة مع:
    payment_method_id, fee_amount, fee_bearer,
    fee_percentage, fee_fixed, fee_added_to_total
   ↓
[5] تحديث المخزون تلقائياً
   ↓
[?] fee_bearer = merchant؟
   ├── ✅ نعم → إنشاء record في payment_fee_expenses تلقائياً
   │              يظهر في تقرير المصروفات تحت "رسوم الدفع الإلكتروني"
   └── ❌ لا  → لا يوجد مصروف
   ↓
[END ✅] الفاتورة مكتملة — الـ fee مرصودة بشكل صحيح
```

### 13.2 قواعد الـ Fee Flow

| الحالة | ما يحدث |
|---|---|
| كاش أو fee_type = none | البيع يكمل مباشرة بدون أي fee logic |
| fee_bearer = customer | الإجمالي يزيد — العميل يدفع أكتر |
| fee_bearer = merchant | الإجمالي ثابت — record في payment_fee_expenses |
| fee_bearer = negotiable | الكاشير يختار وقت البيع |
| مرتجع فاتورة فيها fee | fee_amount يُرجع أو يُحسم حسب fee_bearer |

### 13.3 تدفق إعداد طرق الدفع (Super Admin)

```
[START] Super Admin يفتح إعدادات → طرق الدفع
   ↓
[1] إضافة طريقة دفع جديدة أو تعديل موجودة
   ↓
[2] تحديد:
    - الاسم (فيزا / فلوسة / إنستاباي)
    - النوع (card / wallet / bnpl / cash)
    - fee_type (none / percentage / fixed / both)
    - fee_percentage و/أو fee_fixed
    - fee_bearer (customer / merchant / negotiable)
   ↓
[3] حفظ في payment_methods
   ↓
[END ✅] تظهر في شاشة الـ POS للكاشيرين فوراً
```
